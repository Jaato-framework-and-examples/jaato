# References

Reference sources provide documentation and context that agents can access
during a session. Each JSON file here defines one reference entry.

## Reference Schema

```json
{
  "id": "unique-identifier",
  "name": "Human-Readable Name",
  "description": "Brief description of what this reference contains.",
  "type": "local",
  "path": "./docs/architecture.md",
  "mode": "selectable",
  "tags": ["architecture", "design"],
  "fetchHint": "Read the Overview section first."
}
```

## Fields

| Field | Required | Description |
|-------|----------|-------------|
| `id` | Yes | Unique identifier (lowercase, hyphens) |
| `name` | Yes | Display name |
| `description` | Yes | What the reference contains |
| `type` | Yes | `"local"` (file), `"url"` (web), `"inline"` (embedded text) |
| `path` | For local | Relative or absolute path to the file/directory |
| `url` | For url | Web URL to fetch |
| `content` | For inline | The reference text itself |
| `mode` | No | `"auto"` (always loaded) or `"selectable"` (user chooses). Default: `"selectable"` |
| `tags` | No | Tags for filtering and organization |
| `fetchHint` | No | Hint for the agent on what to read first |

## Auto-Discovery

Files placed in `.jaato/references/` are automatically discovered. Each `.json`
file should contain a single reference object (not an array).

## Knowledge Bundles

A **bundle** is a self-contained unit of reference knowledge: a directory
holding its own set of reference JSONs, marked by a `bundle.json` manifest.
The directory `.jaato/references/` itself is the *root bundle*. Each
immediate subdirectory carrying a `bundle.json` becomes an additional
bundle:

```
.jaato/references/
├── bundle.json                    # marks the root bundle
├── embedding_config.json          # OPTIONAL: its vector index
├── references.embeddings.npy      # the index's sidecar matrix
├── project-docs.json
└── teammate-kb/                   # a second bundle (dropped in as-is)
    ├── bundle.json
    └── deploy-runbook.json        # no index: definitions only
```

**A bundle and a vector index are two different things.** `bundle.json` is
the claim on the directory; `embedding_config.json` describes an embedding
index that may or may not be there. A bundle with no index is a perfectly
ordinary bundle — it is discovered, packed and shipped like any other; it
simply cannot be matched semantically. Run `references reconcile <bundle>`
in a workspace that has an embedding provider to give it one.

- Bundles are independent: an indexed bundle can use a different
  `embedding_model` than the root; semantic matching simply skips bundles
  whose model does not match the active embedding provider.
- Use `references bundles` to inspect the loaded set and their status.
- Use `references reconcile [<bundle>]` to embed newly-dropped references
  and prune orphan rows without restarting the session.
- Subdirectories without a `bundle.json` are **ignored** — they do not
  merge into the root bundle. Being ignored is the point: it is what keeps
  an unrelated folder dropped in here out of the catalog.

## Bundle Manifest

`bundle.json` marks the directory. Every field in it is optional and
informational — its *presence* is what declares the bundle:

```json
{
  "name": "teammate-kb",
  "description": "Deployment runbooks from the platform team"
}
```

## Embedding Config

When using semantic matching (generated by `gen-references`), an
`embedding_config.json` file sits alongside `bundle.json` and the
reference files. It is optional: a bundle without one is still a bundle.

```json
{
  "embedding_model": "all-MiniLM-L6-v2",
  "embedding_dimensions": 384,
  "embedding_sidecar": "references.embeddings.npy",
  "rows": ["my-ref", "another-ref"]
}
```

| Field | Description |
|-------|-------------|
| `embedding_model` | sentence-transformers model used to produce embeddings |
| `embedding_dimensions` | Vector dimensionality (must match the `.npy` sidecar) |
| `embedding_sidecar` | Filename of the `.npy` matrix (relative to this directory) |
| `rows` | Ordered list of reference ids — `rows[i]` is the id whose vector lives at matrix row `i` |

The sidecar `.npy` file contains one row per embedded reference. Each reference
carries only a fingerprint under the optional `embedding` property; the row
position is derived from the `rows` list above, so dropping in a new reference
never has to agree with existing references on numbering:

```json
{
  "id": "my-ref",
  "name": "My Reference",
  "embedding": { "source_hash": "sha256:a1b2c3..." }
}
```

## Modes

- **auto**: Reference is always included in the agent's context. Use sparingly
  for foundational docs that every task needs.
- **selectable**: Agent can choose to load the reference when relevant. Better
  for large reference sets.
